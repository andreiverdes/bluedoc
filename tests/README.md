# Tests

Run `python3 -m unittest discover -s tests` from the repo root (Python 3.9+, standard library only; `node` on the `PATH` adds the template-function checks, which are skipped without it; `BLUEDOC_BROWSER_TESTS=1` adds the page tests, which drive headless Chrome, found in its usual places or named by `BLUEDOC_CHROME`). Each test works on copies of `skills/bluedoc/examples/` in a temp folder with its own `BLUEDOC_HOME`, and the server tests run `serve.py run` on a free port, so nothing touches `~/.bluedoc` or a running server; the helpers send the temp home's key with every request that sends `X-Bluedoc`, as an unlocked page does. The eight suites are `test_golden_examples` (the examples build clean and match `docs/examples/*.html`; regenerate those with `build.py <example> -o docs/examples/<name>.html` after a template change), `test_security` (script-injection probes against `build.validate`, `build.build` and the template's `safeUrl`, `inline` and `num`, JSON blocks that parse as served when a doc quotes `<!--`, a diff ref that must not run the repo's textconv command, design screens framed with `sandbox="allow-scripts"` only and served with the sandbox CSP; with the browser, an escape screen that tries the parent page, storage, the server, the network, top navigation, popups and forms, framed and on its own), `test_server_guards` (path traversal, Host, cross-site POST and `wait` header checks, 400 for a bad `Content-Length` or `wait` timeout, and the design screen route: only a board's artboards and revs, no `X-Frame-Options`, doc pages still unframable), `test_state` (the `/__bluedoc/state` guards and limits, a PUT and GET round trip, the seed, an import that adds only missing keys, state and replies across a restart, approvals bound to the doc the page showed and to its content, and the one-time import of older reply files), `test_page_state` (a doc's URL that a wider folder keeps; with the browser, the page's outbox: two paths with one doc id, a write answered with 404, Approve after an unseen edit, and a doc that quotes `<!--`), `test_resolves` (a doc's `resolves` must be a list of short comment ids, `patch --resolves` rewrites it on a bump and appends with `--no-bump`, the history keeps each revision's list; with the browser, the reply Markdown names each comment's id, and a reload after a patch that lists one resolves that open comment as the agent's, leaves pending comments and unknown ids alone, and resolves a reopened one again only for a newer revision), `test_key_roundtrip` (every key the annotator's `keyOf` emits on the examples resolves in `build.py patch`, `SKILL.md` and `references/schema.md` list every key form, and the inspector's `el:` keys on the design example name a screen file and a selector) and `test_design` (the Acme Fit design example builds clean with two revs in its history, the board contract and fields, screen-file lint, screen HTML per revision and the approval hash, and the screen route's declared, undeclared and missing framework files).
