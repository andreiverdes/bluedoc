`test_manifests` pins the Codex and Copilot CLI manifest layout: no root `plugin.json` declares an Agent Plugins `$schema` (with one, Codex 0.163 skips `.codex-plugin/` and loads no plugin hooks); `.codex-plugin/plugin.json` names the skills and the `Stop` hook, `.plugin/plugin.json` (Copilot) the skills, its commands and the `preToolUse` hook on `exit_plan_mode`, all inside the repo. `test_commands` checks their versions.

`test_layout`, `test_patch_paths` and `test_schema_cards` cover the authoring surface: every doc bluedoc writes is minified JSON, and a pretty doc is migrated on build, patch, `open` and `build.py migrate` with equal content and no new revision; nested `--set a/b/c=v` changes one field and its errors list the ids there, `--append --at` and `--move` place items; each block type, part and doc type has a `build.py schema` card listing every field the validator reads, with an example that validates. `test_server_guards.ServerCopy` deletes the install a server was opened from and still gets pages, then opens other code and sees the old `app/` copy gone.

`test_checklist_kinds` covers the two kinds of checklist and evidence in the build: a list mixing decisions and progress items fails on a new revision and only warns on a doc without history; a decision list after a progress list warns; evidence on steps and progress items (md, code, a media file, a local or `http(s)` link) builds clean; evidence on a decision, an entry with nothing to show, a link with another scheme or an absolute path, and a missing image are errors, and a dead local link a warning; an evidence `pin` (a full sha, or a null commit with a reason) builds clean and a short sha, a dirty pin without `tree`, an absolute repo, a bad time or empty `paths` are errors.

`test_replies` covers conversations, several answers and option explanations on the data side: `build.py patch item:<cl>/<item> --reply` and `ann:<id> --reply` append `{rev, md}` stamped with the bumped rev (the current one with `--no-bump`), with `--resolves`, keeping the previous rev in the history, and refuse a reply on another key, an `ann:` key with other options, a bad comment id, an empty or oversized reply; the build checks `replies` and `threads` and warns on a rev the history lacks; `multi` takes lists of distinct known ids and a list without it is an error, as is `multi` on a progress item or on a brief's `theme`; the home index joins a multi item's ids and an approval keeps list picks; an approval carries over a reply-only rev and over the same multi pick in another order; a doc made by `build.py new plan` (or built first now, which writes `created` into its history) fails on an option without `md`, naming item and option, while an older doc builds with no error and no warning; and `serve.value_ok`/`state_ops` accept and refuse item `:thread` lists, multi pick values and an annotation's `thread` and `draft`.
